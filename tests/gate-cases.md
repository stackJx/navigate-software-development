# 门禁回归用例

改动 `SKILL.md` 或任一 reference 后，用本组用例自查门禁判定是否漂移。

**怎么跑**：把「输入」逐条作为用户消息发给加载了本 Skill 的模型，对照「期望」检查四项——是否输出三章节、DDD 是否命中及档位、TDD 是否命中、默认停止点。全部符合才算无回归。

**判定规则**：期望列写的是**必须成立**的结论。模型可以比期望更详细，但不能给出不同的门禁结论；跳过项必须有一句理由，不能沉默省略。

## A. 门禁组合

| # | 输入 | 三章节 | DDD | TDD | Git Flow | 停止点 |
| --- | --- | --- | --- | --- | --- | --- |
| A1 | 「给商品列表加按分类筛选，只要需求和开发思路，先不写代码。」 | 必须 | 跳过（L0，只读查询薄规则） | 跳过（用户只要方案） | 跳过（只要方案，不产生变更） | 输出合同后停止 |
| A2 | 「满 100 减 20 的券，订单正好 100 元时用不了。修一下。」 | 必须 | 跳过（L0，单条计算规则） | **命中**（可稳定复现 + 需回归） | 跳过（未显式声明版本控制） | 完成修复与验证 |
| A3 | 「用户点两次提交会生成两个订单、扣两次款，修复它。」 | 必须 | **命中 L1**（聚合原子不变量缺失，局部战术） | **命中** | 跳过（未显式声明版本控制） | 幂等键来源是阻塞项 → 等用户确认 |
| A4 | 「为订阅计费业务梳理统一语言、限界上下文和聚合，技术栈未知。」 | 必须 | **命中 L2+**（术语与模型所有权） | 跳过（纯建模，非可执行） | 跳过（纯建模，不产生变更） | 输出合同与领域设计后停止 |
| A5 | 「我们订单服务和库存服务对账老是不一致，帮我理一下。」 | 必须 | **命中 L3**（跨上下文一致性） | 跳过或按需（无实现请求） | 跳过（分析为主，不产生变更） | 输出合同与一致性矩阵后停止 |
| A6 | 「给用户表加个 nickname 字段，前后端都要能存能显示。」 | 必须 | 跳过（L0，薄 CRUD） | 按仓库是否已有可运行测试判定 | 跳过（未显式声明版本控制） | 完成实现与验证 |
| A7 | 「实现批量审批功能。」 | 必须 | 按业务规则厚度判定，无状态迁移则跳过 | **命中**（权限 + 状态 + 副作用） | 跳过（未显式声明版本控制） | 完成实现与验证 |
| A8 | 「我是单人仓库，本地实验性改个脚本，提交一下。」 | 必须（可走快速通道） | 跳过（L0） | 跳过（无业务规则） | 跳过（未显式声明；「提交一下」是执行动作非策略声明） | 完成变更与一眼核验 |
| A9 | 「团队仓库 main 是受保护的，帮我把审批功能合上去。」 | 必须 | 按业务规则厚度判定 | **命中** | **命中 L2**（用户显式要求合入受保护主干 → 显式声明） | 完成实现、合并与验证 |

## B. 微变更快速通道

| # | 输入 | 期望 |
| --- | --- | --- |
| B1 | 「README 里『限届上下文』写错了，改成『限界上下文』。」 | 走快速通道：三章节各一到两行，**仍在编辑前输出**；不得完全省略标题 |
| B2 | 「把这个文件里的 `tmp` 变量改名成 `pendingOrder`。」 | 走快速通道（单文件、纯重命名、无行为变更） |
| B3 | 「把超时时间从 30 秒改成 60 秒。」 | **不走**快速通道——改变可观察行为且触及外部契约，走完整合同 |
| B4 | 「把这个日志级别从 info 调成 debug，顺便把重试次数改成 5。」 | **不走**快速通道——涉及两处且重试次数影响失败恢复语义 |
| B5 | 「升级一下 lodash 版本。」 | **不走**快速通道——触及依赖版本，走完整合同 |

## C. 阶段边界

| # | 场景 | 期望 |
| --- | --- | --- |
| C1 | 判断 TDD 门禁时想确认现有测试是否为绿 | 阶段 A **不实跑测试**，只读测试文件与既有 CI 结果；绿灯基线放到合同发出后 |
| C2 | 想先跑一次格式化工具再看代码 | **禁止**——格式化写文件，属变更动作，须先输出合同 |
| C3 | 不确定 `make check` 是否会写产物 | 按变更动作处理，先输出合同 |
| C4 | 实施到一半发现范围需要扩大 | 暂停变更，**重新输出修订后的三章节**，不在最终答复里静默改基线 |
| C5 | 模型已经改了文件，才在最终答复里补写三章节 | **违规**——发送最终答复不算满足前置门禁 |
| C6 | 阶段 A 想先建分支再输出合同 | **违规**——建分支/提交/推送属变更动作，须先输出合同；只读查看 Git 状态可以 |

## D. 委派降级

| # | 场景 | 期望 |
| --- | --- | --- |
| D1 | 当前已在子代理内执行 | 递归守卫触发 → solo，不再 spawn |
| D2 | Codex 未开启 `multi_agent` | 降级 solo，并在答复中一句话说明原因 |
| D3 | 三个实现类切片会同时改同一文件 | 不并行——实现类默认串行，或用 worktree 隔离 |
| D4 | 两个完全独立且都耗时的分析子任务 | 可并行——判据是边界质量而非子任务个数 |
| D5 | 子代理返回了与需求不符的结论 | 主智能体打回重派或自行补做，**不得盲目采纳** |

## E. 不应触发

| # | 输入 | 期望 |
| --- | --- | --- |
| E1 | 「这个函数是干什么的？」 | 纯问答，不输出三章节 |
| E2 | 「帮我看看这份日志里的报错是什么意思。」 | 纯诊断解释，不进入开发合同；若用户接着要求修复才触发 |
| E3 | 「解释一下什么是限界上下文。」 | 概念问答，不套用开发前合同 |

## F. 已知易错点

改动后重点复查这几处，历史上最容易被改坏：

- **跳过 DDD ≠ 跳过边界检查**：A2 仍需确认规则所有者唯一；
- **三个可选门禁独立**：Git Flow 与 TDD、DDD 各自按门禁命中与否；A2 是「TDD 命中 + DDD 跳过」（不要因为写测试就顺手铺领域模型），A8 是「三个全跳过」，A9 是「TDD + Git Flow 命中、DDD 可能跳过」，允许任意组合；
- **Git Flow 仅显式声明才命中**：仓库多人协作、有共享主干或已有分支模型本身不再触发；A7 是多人实现请求但未显式声明版本控制 → 跳过，A9 是用户显式要求合入受保护主干 → 命中 L2。裸的「提交一下 / 合上去」是执行动作，不算声明；
- **快速通道不是后门**：B 组任一条件不满足即走完整合同，判断不确定时也走完整合同；
- **未命中要写理由**：跳过 DDD/TDD/Git Flow 必须有一句话，不能留空标题也不能沉默省略；
- **档位不由项目规模决定**：A3 是大系统里的局部缺陷，仍是 DDD L1 而非 L4；Git Flow 命中后的档位由用户显式要求的协作形态决定（合入受保护主干 → L2），不由仓库大小决定；
- **建分支是变更动作**：阶段 A 只允许只读查看 Git 状态，建分支/提交/推送须等合同发出后。
